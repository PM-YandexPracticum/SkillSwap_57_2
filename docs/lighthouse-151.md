## Найденная проблема и исправление

До изменений страница фотографии получила Performance 73, Accessibility 98.
Галерея запрашивала оригинальные фотографии Cloudinary, включая скрытые слайды.
В исходном замере эти запросы передали суммарно 13 522 210 байт.

Исправления:

1. Для главных изображений Cloudinary запрашивается версия не больше 800×800,
   для миниатюр — не больше 200×200, с сохранением пропорций.
2. `q_auto` и `f_auto` позволяют Cloudinary выбирать качество и формат выдачи.
3. Включена отложенная загрузка слайдов средствами `react-image-gallery`.
4. Первое изображение загружается сразу с высоким приоритетом; остальные — отложенно.

В первом итоговом замере запросы галереи передали 81 563 байта,
LCP сократился с 9,2 до 0,7 секунды. Эти значения относятся к указанным запускам;
при повторении они могут меняться из-за сети, CDN и нагрузки компьютера.

Исходные фотографии, их порядок и количество сохранены. Оптимизация применяется
при отображении. Ссылки других хостингов, локальные пути, `blob:` и `data:`
остаются исходными. Зависимости приложения не менялись.

Основание для параметров выдачи:
[документация Cloudinary](https://cloudinary.com/documentation/image_optimization).

## Как повторить замер

В первом терминале из корня проекта:

```sh
npm run build
npm run preview -- --host 127.0.0.1 --port 4173 --strictPort
```

Во втором терминале, с Node.js 22 или новее, например для главной:

```sh
npx --yes lighthouse@13.5.0 http://127.0.0.1:4173/ --preset=desktop --only-categories=performance,accessibility --chrome-flags=--headless --output=html --output=json --output-path=/private/tmp/skillswap-home
```

Для остальных публичных страниц заменить URL. URL навыка с `?` нужно заключить
в кавычки. Отчёты `.report.html` и `.report.json` появятся по указанному пути.
Во время замера не запускать другие сборки и аудиты параллельно.

### Избранное и личные данные

1. В отдельном профиле Chrome открыть собранный сайт на порту 4173.
2. Пройти регистрацию и подтверждение предложения до перехода на главную.
3. Добавить карточку в избранное. Открыть `/favorites`, убедиться, что карточка видна.
4. Открыть DevTools → Lighthouse, выбрать Navigation, Desktop,
   Performance и Accessibility. Отключить Clear storage, чтобы сохранить сессию.
5. Выполнить замер и сохранить HTML/JSON-отчёты.
6. Повторить на `/profile?section=personal`, предварительно убедившись,
   что открылась форма с полями «Почта», «Имя», «Город» и кнопкой «Сохранить».

Встроенный `demo@skillswap.ru` не подходит для проверки формы: у него нет записи
профиля, и показывается ошибка загрузки. Предварительный отчёт для этого состояния
исключён из итогов. Оценка страницы ошибки не заменяет проверку формы.

Способ проверки авторизованных страниц:
[инструкция Lighthouse](https://github.com/GoogleChrome/lighthouse/blob/main/docs/authenticated-pages.md).

## Границы результата

Lighthouse проверяет текущий экран автоматически. Эти отчёты не подтверждают
полную доступность всех состояний, работу всего MVP или показатели будущего деплоя.
Первый шаг регистрации проверен как страница; остальные шаги использовались
для создания тестового пользователя, отдельные Lighthouse-замеры для них не делались.

В отчётах остались замечания, не препятствующие порогам: доступные имена части
чекбоксов фильтра, контраст зелёных ссылок, порядок заголовков и имя миниатюры
со счётчиком. Они не отключались и не исключались из оценки.
